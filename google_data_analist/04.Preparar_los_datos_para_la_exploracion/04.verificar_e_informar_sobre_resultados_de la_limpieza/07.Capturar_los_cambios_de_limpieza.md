# Documentación y Seguimiento de Cambios en la Limpieza de Datos

Una vez que los datos están limpios, es fundamental abordar el rastro que ha dejado el proceso. La información incorrecta desaparece, pero los cambios realizados poseen un valor estratégico que debe ser conservado y comunicado.

### La Importancia de la Documentación

La **documentación** es el proceso de seguimiento de los cambios, adiciones, eliminaciones y errores relacionados con el esfuerzo de limpieza. Es comparable a la labor de un equipo forense en una escena del crimen:

* **Evidencia:** Los errores de datos son el "delito".
* **Investigación:** La limpieza consiste en recopilar pruebas.
* **Informe:** La documentación detalla exactamente qué ocurrió para su revisión por pares o ante un tribunal (o partes interesadas).

### Beneficios de Registrar la Evolución de los Datos

Tener un registro detallado de cómo evolucionó un conjunto de datos cumple tres funciones vitales:

1. **Recuperación de errores:**
* Funciona como una "hoja de trucos" para no tener que recordar cambios realizados meses atrás.
* *Consejo profesional:* Es mejor crear una **tabla limpia nueva** en lugar de sobrescribir la original para conservar los datos fuente.


2. **Continuidad informativa:**
* Si te ausentas o asciendes, tu sucesor tendrá una referencia clara de lo que se hizo.


3. **Determinación de la calidad:**
* Ayuda a decidir si un conjunto de datos es confiable o si, debido a la gran cantidad de errores encontrados, debería evitarse en el futuro.



### Herramientas de Registro (Change Logs)

Un **registro de cambios** es un archivo con la lista cronológica de las modificaciones.

#### En Hojas de Cálculo:

* **Historial de versiones:** Permite ver quién hizo cambios y cuándo en toda la hoja (Pestaña Archivo > Historial de versiones).
* **Historial de edición de celdas:** Al hacer clic derecho en una celda específica, se puede ver su evolución particular.

#### En SQL:

* **Historial de consultas:** Registra cada consulta ejecutada, permitiendo volver a versiones anteriores si una nueva consulta "bloquea" el sistema.
* **Comentarios en el código:** Agregar notas mientras se limpia ayuda a construir el registro de cambios final.
* **Repositorios:** Algunas empresas usan software avanzado donde cada consulta se "confirma" (commit) explicando el porqué del cambio.

## Conceptos Clave y Definiciones

| Concepto | Definición |
| --- | --- |
| **Documentación** | El acto de registrar formalmente cada modificación (cambios, adiciones, eliminaciones) realizada durante la limpieza de datos para su futura referencia. |
| **Registro de Cambios (Change Log)** | Archivo que contiene una lista ordenada cronológicamente de las modificaciones realizadas en un proyecto o conjunto de datos. |
| **Historial de Versiones** | Herramienta de software que guarda "capturas" del estado de un archivo en diferentes momentos, permitiendo restaurar puntos anteriores. |
| **Consulta (Query)** | Instrucción en lenguaje SQL utilizada para interactuar con una base de datos (extraer, limpiar o modificar datos). |
| **Comentarios (SQL)** | Notas escritas dentro del código SQL (usualmente precedidas por `--`) que no se ejecutan, pero sirven para explicar la lógica a otros analistas. |
| **Revisión por Pares** | Proceso en el que otros analistas examinan tu documentación y datos para validar la calidad y precisión del trabajo realizado. |
| **Tabla Limpia** | Una copia nueva y depurada de los datos que se crea manteniendo intacta la tabla original (datos sucios) para fines de respaldo. |
